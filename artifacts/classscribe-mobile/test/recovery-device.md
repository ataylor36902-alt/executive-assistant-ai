# Recovery on a native phone (release check)

Run on **both iOS and Android** in a development build / Expo Go with a disposable personal library. The Node screen test (`pnpm --filter @workspace/classscribe-mobile test:recovery-audio`) checks the screen logic with simulated native boundaries; it cannot establish that Expo's file listing or audio output works on a phone. Record the device, OS, build, and pass/fail for each step below. Do not mark the native check passed from the Node test alone.

1. Open **Account → Recover missing recordings**. Tap **Create sample recording for recovery check** once. This writes a one-second, audible WAV to the app's *documents root* with a unique `classscribe-recovery-check-*.wav` name using Expo's native `File.write`. Copy the displayed sample name. Do not create another sample during this run.
2. Confirm the sample appears under **Found on this phone** after the automatic scan. Tap **Scan this phone again** and confirm it remains listed exactly once. If the sample is absent or an error is shown, the native documents scan failed.
3. Tap **Preview audio**, wait for **Play** to become enabled, tap **Play** and hear the tone through the phone speaker. Tap **Pause**, then **Close preview**. A visible player without audible output is not a pass.
4. Select the sample checkbox, choose an existing **personal** course (not an example course), and leave the **After restoring, upload selected audio** checkbox **off**. Verify **Transcription requests from recovery: 0** before tapping **Restore 1 selected recording** and again after seeing **1 recording restored to your library**. Do not toggle transcription on: the check is specifically for the unchecked path. This diagnostic counts calls from this recovery screen to `processRecording`; network traffic from unrelated screens is not included.
5. Open that course, open the restored lecture, and play its recording. Confirm its title/audio is present in the selected personal course, the file still plays, and no transcript/AI analysis was generated by recovery.
6. Fully terminate the app (not just navigate away) and reopen the same library. Open the course and lecture again, and play the recording. Return to **Recover missing recordings** and tap **Scan this phone again**. The sample must **not** be offered for recovery again: its persisted lecture link excludes it. Other unrelated orphan files may still appear. The WAV remains on the phone; recovery does not delete it.

On a test library that already has a root-level recording linked by `audioName` alone, also verify that recording does not appear in the scan. Do not use a real student's library to generate test recordings.

## Damaged-file preview check

1. In a disposable library, tap **Create damaged recording for recovery check** and **Create sample recording for recovery check**. The damaged fixture is a nonempty `.wav` containing invalid audio bytes, so the real documents scanner should list it.
2. Select both fixtures. Preview the damaged file. Confirm **This recording cannot be previewed** appears (or **This recording did not finish loading** within 15 seconds if the native decoder does not report an error). There must not be an indefinite **Loading audio…** button or an app crash.
3. Hide the preview and confirm the message remains on that file. Tap **Skip this recording**. Confirm only the healthy recording is selected, and preview/play its audible tone.
4. With transcription off, restore the healthy recording and confirm it plays in the chosen course. Scan again: the damaged file should reappear, showing that skipping did not delete it. No lecture or transcription should have been created for the skipped file.
5. Record device/OS/build and results separately for iOS and Android. If no native device is available, report this check as **not run**, not passed.

For library separation, record and save an audio lecture in disposable library A, then switch to disposable library B on the same phone. Confirm the new recording does not appear in B's recovery scan. Record an orphan in B by stopping after its native file is saved but before the lecture link is stored, then confirm only B's scoped orphan appears in B's scan. Switch back to A and check that its lecture plays. Older files stored without a library owner can still appear in both scans and must be identified by listening before selecting them; neither scan should move, remove, or upload them without explicit recovery/transcription choices. Finally replace A's sync code and confirm the linked lecture plays under the replacement code.
